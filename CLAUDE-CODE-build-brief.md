## Objective

A self-contained, cross-platform, zero-API-key Python repo. Participants run it in **GitHub Codespaces** (primary) or **Google Colab** (fallback), on Windows or Mac browsers. The two hands-on labs let a participant watch a deterministic failure, apply a one-line fix, and confirm it with a passing test.

The two teaching failures the harness must produce **deterministically, every run:**
1. **Write conflict** — two agent runs write to the same client record; an obligation is duplicated / a record is half-overwritten.
2. **State contamination** — two client runs share mutable state; client Alpha's briefing ends up containing client Beta's data.

---

## Hard constraints (these drive the whole design)

- **No network at runtime.** LLM and embeddings are served from pre-recorded fixtures. An optional live-LLM path may exist but must be gated behind `NOVA_LIVE_LLM=1` and off by default. No other outbound calls, ever.
- **Determinism.** Every engineered failure must occur on 100% of runs across machines. No wall-clock timing, no real threads racing, no unseeded randomness. Concurrency is *simulated* via a scripted cooperative scheduler (spec below).
- **Cross-platform, no OS-specific code.** `pathlib` everywhere; no shell-outs; no platform branches. Identical behaviour on Codespaces (Linux) and Colab.
- **Legible failures.** Use `rich` so corrupted records and wrong-client briefings are obvious when screen-shared at 720p.
- **Python 3.11.9**, dependencies hard-pinned.
- **Type hints and docstrings on every public function.** The code is teaching material — clarity beats cleverness. The agent loop must be transparent: every step visible, nothing hidden in abstractions.

## Component specs

### `nova/models.py`
Pydantic models: `ClientDocument`, `Obligation` (incl. `client_id`, `text`, `source_doc`, optional `idempotency_key`), `Briefing` (`client_id`, `content`, `obligations: list[Obligation]`), `TraceEvent`.

### `nova/store.py`
SQLite store. Neutral primitives plus **deliberately naive** convenience writes the labs expose as broken.
```python
class RecordStore:
    def __init__(self, db_path: Path) -> None: ...
    def init_schema(self) -> None: ...
    def get_client(self, client_id: str) -> dict: ...
    def append_obligation(self, ob: Obligation) -> None:
        """NAIVE: inserts unconditionally. No dedup, no idempotency check."""
    def set_briefing(self, client_id: str, content: str) -> None:
        """NAIVE: last-write-wins, no version check."""
    def get_obligations(self, client_id: str) -> list[Obligation]: ...
    def execute(self, sql: str, params: tuple = ()) -> list:
        """Primitive for participant fixes to build on (e.g. version checks)."""
```
Schema: `clients`, `documents`, `obligations`, `briefings`. Include a `version` column on `briefings` that naive `set_briefing` ignores (participants use it).

### `nova/frozen_llm.py`
```python
class FrozenLLM:
    def __init__(self, fixtures_dir: Path) -> None: ...
    def complete(self, prompt: str) -> str:
        """Return response by sha256(prompt) lookup in fixtures/llm_responses/.
        Raise a clear FixtureMissing error naming the missing key if absent."""
```
Add a build-time recorder active only with `NOVA_LIVE_LLM=1` that calls the real model and writes the fixture, so fixtures can be regenerated. Never called at workshop runtime.

### `nova/embeddings.py`
```python
def embed(text: str, fixtures_dir: Path) -> np.ndarray:
    """Frozen: return pre-computed vector by sha256(text) lookup."""
def search(query_vec: np.ndarray, doc_vecs: np.ndarray, k: int) -> list[int]:
    """Cosine similarity, top-k indices. Pure numpy."""
```

### `nova/agent.py`
Transparent loop, dependencies injected so labs can swap the state backend.
```python
class Agent:
    def __init__(self, store, llm, embeddings, tracer, state) -> None: ...
    def run(self, client_id: str, run_id: str) -> Briefing:
        """retrieve docs -> reason (frozen) -> extract obligations ->
        write obligations -> draft briefing -> return.
        Holds working state in self.state across steps.
        Emits a trace event at each step."""
```
`state` exposes `get(run_id)` / `set(run_id, data)`. Provide a naive `SharedState` (ignores `run_id`); participants build `IsolatedState` in the State lab.

### `nova/scheduler.py` — get this exactly right
Simulated concurrency via **scripted cooperative stepping**, not threads.
```python
class Scheduler:
    def __init__(self, script: list[str]) -> None:
        """script e.g. ['A:read','B:read','A:write','B:write'] — the
        interleaving that forces the conflict, applied identically every run."""
    def run(self, run_a: Callable, run_b: Callable) -> tuple:
        """Step both runs to completion following the script. Deterministic:
        identical inputs + script => identical outcome, 20/20."""
```
Express each agent run as a generator yielding at checkpoints (`read`, `reason`, `write`, `draft`); the scheduler drives them per the script. No `time.sleep`, no threads, no unseeded `random`. **Acceptance: each lab's naive path fails 20/20 runs.**

### `nova/trace.py`
```python
class Tracer:
    def __init__(self, out_path: Path) -> None: ...
    def event(self, run_id: str, step: str, data: dict) -> None: ...
    def dump(self) -> list[TraceEvent]: ...
```
Emit JSON lines: run_id, step, retrieved context, pre-write state snapshot, the write, the decision point.

## Lab & demo harness specs

### Module 02 — Write Problems *(hands-on lab — build fully)*
- **`naive.py`** — two `Agent.run` calls for the *same* client via `Scheduler` with a conflict script; print (via `rich`) the record showing the duplicated obligation / half-overwrite. `python naive.py` shows the corruption.
- **`your_fix.py`** — scaffold with `guarded_write(store, ob)` containing `# TODO: add your guard (idempotency key OR optimistic version check)` and a naive body. Participants edit only this file.
- **`test_write.py`** — pytest: run the conflict script through `guarded_write`; assert no duplicate obligation and correct final state. **Fails with the naive body, passes with a correct guard.**
- **`_reference/write_fix.py`** — a correct guard, used only to validate the test.
- **`LAB.md`** — numbered mechanical steps: run naive → observe → read failure → fix → `pytest` → green. No teaching narration.

### Module 03 — State, Memory & Recovery *(hands-on lab — build fully)*
- **`naive_state.py`** — two `Agent.run` calls for *different* clients (Alpha, Beta) sharing `SharedState` via `Scheduler` with a contamination script. Print both briefings via `rich`; Alpha's must visibly contain Beta's data.
- **`your_fix.py`** — scaffold: task 1 build `IsolatedState` (namespace by run_id); task 2 add a checkpoint so a killed run recovers. TODO markers; participants edit only this file.
- **`test_state.py`** — assert Alpha's briefing contains only Alpha data (isolation) and a killed-and-resumed run completes correctly (recovery). Fails naive, passes reference.
- **`_reference/state_fix.py`** — correct solution to validate tests.
- **`LAB.md`** — mechanical steps only.

### Module 04 — Provenance *(facilitator demo tooling — no participant lab)*
- **`scripts/generate_trace.py`** — runs the naive state failure with tracing on to produce `fixtures/traces/incident_047.json` (inputs, retrieved context, pre-write state, the contaminating write, the decision point).
- **`walk_trace.py`** — a `rich`-formatted forensic viewer the facilitator drives live: reconstructs the "why" from the trace, and shows a contrast where no trace was captured and the question is unanswerable.
- **`LAB.md`** — the facilitator demo steps (mechanical). **No `your_fix.py`, no test, no participant code.** This block is a demo, not a lab.
